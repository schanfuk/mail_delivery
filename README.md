# 福岡学生情報メルマガ

福岡の学生向けに、毎日朝のお得情報・チャンス情報を自動配信するメールマガジンシステムです。Google Apps Script (GAS) で動作し、複数の RSS フィードから「お得情報」「ハッカソン」「留学」「インターン」の 4 カテゴリを自動収集 → スコアリング → デザインされた HTML メールで配信します。

ご当地ニュースだけでなく、全国区のクーポンや学割キャンペーンも適切に拾えるよう、カテゴリごとに「ご当地枠 / 全国区枠」を分けて採用する仕組みになっています。

---

## 主な機能

- **RSS の自動巡回**: スプレッドシートに登録した複数 URL を `UrlFetchApp.fetchAll` で並列取得
- **ご当地 / 全国区の枠分け採用**: カテゴリごとに地域記事と全国記事の枠を独立に設定し、それぞれの中で上位を採用
- **キーワードスコアリング**: カテゴリ別キーワード (+1) / 緊急性ワード (+2) / 除外ワード (-3) / 全国ブランド (+1) で記事を採点
- **昨日の記事のみ抽出**: `pubDate` で日付フィルタ。古い記事や未来日付の混入を防止
- **重複排除**: GUID 完全一致 + タイトル先頭 10 文字の正規化マッチ(全角半角・記号差を吸収)
- **カテゴリ別シート保存**: カテゴリ名のシートが自動生成され、取得履歴が蓄積される
- **GCS バックアップ (オプション)**: 取得した記事を JSON 形式で Google Cloud Storage に保存。未設定でも動作可能
- **HTML メール配信**: カテゴリごとに色分けされ、記事ブロック全体がクリック可能な、レスポンシブ対応の HTML メールを Gmail で一斉送信

## スプレッドシート構成

このスクリプトは 1 つのスプレッドシートに以下 3 種類のシートが存在することを前提に動作します。

### 1. `設定` シート (RSS フィード一覧)

| A 列: カテゴリ | B 列: 説明(任意) | C 列: RSS URL |
| --- | --- | --- |
| お得情報・クーポン | PR TIMES 学割タグ | https://prtimes.jp/topics/keywords/学割.rdf |
| ハッカソン・コンテスト | Connpass | https://connpass.com/explore/category/hackathon.atom |
| 留学・海外プログラム | JASSO | https://www.jasso.go.jp/... |
| インターン・プログラム | 福岡市インターン情報 | https://... |

カテゴリ名は `CATEGORY_LIMITS` / `PLUS_WORDS` のキーと **完全一致** させる必要があります。

### 2. `配信リスト` シート (送信先メール)

| A 列: 氏名(任意) | B 列: メールアドレス |
| --- | --- |
| 山田太郎 | yamada@example.com |
| 佐藤花子 | sato@example.com |

B 列のみ使用。空欄行は自動でスキップされます。

### 3. カテゴリ別シート (自動生成)

スクリプト初回実行時に各カテゴリ名のシートが自動作成されます。手動で作る必要はありません。

| 取得日時 | カテゴリ | 記事タイトル | URL | ID(GUID) |
| --- | --- | --- | --- | --- |

## ご当地 / 全国区の枠分け

各カテゴリで「ご当地枠 (local)」と「全国区枠 (national)」を独立に管理し、それぞれの中で上位を採用します。

```js
const CATEGORY_LIMITS = {
  "お得情報・クーポン":       { local: 2, national: 3 },  // 全国区クーポン多め
  "ハッカソン・コンテスト":   { local: 3, national: 1 },  // ご当地中心
  "留学・海外プログラム":     { local: 2, national: 2 },  // 半々(JASSO等は全国制度)
  "インターン・プログラム":   { local: 3, national: 2 }   // ご当地多め
};
```

**判定ロジック**: `LOCATION_PLUS_WORDS` (`福岡 / 博多 / 天神 / 九州 / Fukuoka`) のいずれかをタイトルに含む記事を「ご当地」、含まない記事を「全国区」に分類します。

**補完動作**: 片方の枠が埋まらない場合(例: 全国区クーポンが2件しか取得できなかった日)は、もう片方のプールから順次補充し、合計件数 (`local + national`) は維持されます。

## スコアリング仕様

`calcScore(title, category)` でタイトル文字列を評価します。

| 要素 | 重み | 例 |
| --- | --- | --- |
| カテゴリ別プラスワード | **+1** | 「学割」「ハッカソン」「奨学金」「インターン」など |
| 緊急性ワード | **+2** | 「募集中」「締切」「発表」「決定」「開催」など |
| 全国ブランド (全国区記事のみ) | **+1** | Amazon / Apple / 楽天 / PayPay など |
| 除外ワード | **-3** | 「終了」「中止」「延期」「PR」「広告」「まとめ」など |

最終的に **スコア 0 以上** の記事のみ採用し、ご当地プール・全国区プールそれぞれの中でスコア降順 → 公開日降順で並べ、枠の上限まで採用します。

地域ワード (`LOCATION_PLUS_WORDS`) はスコア加点には**使わず**、ご当地 / 全国区の振り分け判定にのみ使用します。これにより、両プールが同じ基準で公平に評価されます。

## セットアップ

### 1. スプレッドシートを準備

新規スプレッドシートを作成し、`設定` / `配信リスト` の 2 シートを上記フォーマットで作成。

### 2. GAS エディタにコードを貼り付け

スプレッドシートのメニューから `拡張機能` → `Apps Script` を開き、`コード.gs` に `news_delivery.gs` の中身を貼り付け。

### 3. (任意) GCS バックアップを有効化

GCS バックアップを使う場合のみ、以下を実行してください。**使わない場合は次のステップ 4 に進んで OK** です。

#### 3-1. Cloud Storage バケットを作成

Google Cloud Console で Cloud Storage バケットを作成。

#### 3-2. GCP プロジェクトを紐付け

- GAS エディタ左の歯車アイコン → `Google Cloud Platform (GCP) プロジェクト` で対象 GCP プロジェクト番号を設定
- 該当 GCP プロジェクトで Cloud Storage API を有効化
- 実行ユーザーに `Storage Object Creator` 権限を付与

#### 3-3. スクリプトプロパティにバケット名を保存

GAS エディタで関数選択から `setupBucketName` を選び実行。ダイアログにバケット名を入力して保存。

> 💡 スクリプトプロパティはコードに含まれず GitHub にも上がりません。各環境ごとに個別に設定する仕組みです。

### 4. `appsscript.json` でスコープを追加

GAS エディタの `プロジェクトの設定` → `appsscript.json マニフェスト ファイルをエディタで表示する` にチェック。`appsscript.json` に以下のスコープが含まれていることを確認します。

```json
{
  "oauthScopes": [
    "https://www.googleapis.com/auth/spreadsheets",
    "https://www.googleapis.com/auth/script.send_mail",
    "https://www.googleapis.com/auth/script.external_request",
    "https://www.googleapis.com/auth/devstorage.read_write"
  ]
}
```

GCS を使わない場合、`devstorage.read_write` は不要です。

### 5. トリガーを設定

GAS エディタ左の時計アイコン → `トリガーを追加`:

| 項目 | 設定値 |
| --- | --- |
| 実行する関数 | `fetchAndStoreNews` |
| デプロイ | `Head` |
| イベントソース | 時間主導型 |
| 時間ベースのトリガー | 日付ベース |
| 時刻 | `午前 7 時 〜 8 時` (任意) |

## カスタマイズポイント

| 変数 / 関数 | 役割 | 変更時の注意 |
| --- | --- | --- |
| `CATEGORY_LIMITS` | カテゴリ別の `{ local, national }` 採用件数 | キー名を変えたら `PLUS_WORDS` と `設定` シートも合わせる |
| `PLUS_WORDS` | カテゴリ別の加点キーワード | 配列に追加するだけで反映 |
| `LOCATION_PLUS_WORDS` | ご当地判定ワード | 福岡以外の都市向けに使う場合は書き換え |
| `NATIONAL_BRAND_WORDS` | 全国区プール内の加点ブランド | 学生に刺さるブランドを追加すると全国区で上位に出やすくなる |
| `STRONG_WORDS` | 緊急性ワード | スコア重み(+2) は関数内ハードコード |
| `EXCLUDE_WORDS` | 除外ワード | スコア重み(-3) は関数内ハードコード |
| `CATEGORY_STYLE` | メール内カテゴリの配色 | `color`(濃色) / `border` / `dot` の 3 色セット |
| `CATEGORY_ORDER` | メール内のカテゴリ表示順 | 配列に存在しないカテゴリは末尾に追加される |

### スクリプトプロパティ (機密設定)

| プロパティ名 | 役割 | 設定方法 |
| --- | --- | --- |
| `BUCKET_NAME` | GCS バックアップ先バケット名 | `setupBucketName` 関数を実行、または GAS エディタの `プロジェクトの設定` → `スクリプト プロパティ` で手動追加 |

スクリプトプロパティの値は **コードに含まれず、エクスポートやコピーにも乗りません**。フォーク先ごとに個別に設定する必要があります。

## 関数リファレンス

| 関数 | 役割 |
| --- | --- |
| `setupBucketName()` | 初回セットアップ用。GCSバケット名をスクリプトプロパティに保存 |
| `fetchAndStoreNews()` | メインエントリ。RSS 取得 → 採点 → 枠分け選定 → 保存 → GCS 同期 → メール送信を一括実行 |
| `uploadToGCS(fileName, data)` | JSON を Cloud Storage にアップロード。`BUCKET_NAME` 未設定時は自動スキップ |
| `sendEmailReport(reportData, now, ss)` | HTML メールを生成して `配信リスト` 全員に一斉送信 |
| `calcScore(title, category)` *(closure)* | タイトル文字列からスコアを算出(地域ワードは含まない) |
| `isLocalArticle(title)` *(closure)* | タイトルに地域ワードが含まれるかを判定 |
| `cleanText(t)` *(closure)* | タイトルの先頭 10 文字を正規化(重複判定用) |

## 配信メールのレイアウト

- ダークヘッダー (`#111827`) にメインタイトルと配信日のみのシンプル構成
- カテゴリごとに色分けされたセクション(ピンク / 青 / 緑 / オレンジ)
- 記事はタイトル + 配信元ドメインの 2 段構成
- **記事ブロック全体がクリック可能**(`target="_blank"` で別タブ起動)
- フッターは右寄せで配信日時のみ

## 動作確認

GAS エディタから `fetchAndStoreNews` を手動実行し、以下を確認します。

1. 各カテゴリシートに昨日の記事が追加されているか
2. (GCS有効時) GCS バケットに `backup/news_YYYYMMDD_HHMMSS.json` が生成されているか
3. `配信リスト` のメールアドレスに配信メールが届くか
4. メール内の記事タイトルをクリックして元記事に遷移できるか

新着記事が 0 件の場合はメール配信がスキップされ、ログに「新着記事なし — メール配信スキップ」と出力されます。

## 注意事項

- **無料枠の制約**: Gmail の 1 日あたり送信数上限は 100 通(個人 Google アカウントの場合)。配信リストが多い場合は Workspace アカウントへの切り替えを検討してください。
- **GAS 実行時間制限**: 1 回の実行は 6 分以内。RSS フィードを大量に登録する場合は分割実行を検討。
- **RSS のフォーマット差異**: 現状のパーサは `<channel><item>` 構造の RSS 2.0 を前提としています。Atom 形式のフィードを扱う場合はパース部分の拡張が必要。
- **GCS 認証**: GAS プロジェクトと GCP プロジェクトが正しく紐付いていないと `uploadToGCS` が 401 / 403 で失敗します。
- **配信リストの取り扱い**: `配信リスト` シートのメールアドレスは個人情報です。シートを共有する際は閲覧範囲に注意してください。本リポジトリにはコードのみが含まれ、配信リストや GCS バケット名は含まれません。
